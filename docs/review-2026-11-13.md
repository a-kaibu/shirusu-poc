## 更新 main の CI で追加確認した問題

- R15: CI run `43257264290` の Windows x64/x86 が `deleting_fiber_does_not_end_thread_capture` で失敗。Rust 1.99.1 の Windows TLS destructor 実装は fiber 上で cleanup を省略するため、削除時の誤通知だけでなく実際の thread exit も通知されない。Windows は `.CRT$XLB` の native TLS callback で `DLL_THREAD_DETACH` のみを処理するよう修正。既存の Windows 回帰テストは `2ee423b` の x86 CI で通過。native callback は Loader Lock 下で事前確保済み通知を atomic queue へ積むだけとし、ランタイムのロック取得・解放処理は次の管理パスまたは shutdown で行う。複数スレッドの通知と二重回収もテストする。
- R16: 同 run の fuzz-short は corpus 生成スクリプトの Permission denied で未実行。実行権限を修正し、85 seed の生成を確認した。

- R17: Runner の ReadFile/WriteFile は要求サイズと実バッファ容量を照合せず、ローカル確保した領域を非同期 I/O に渡して呼び出し直後に解放できた。既知のサイズは計画時、保存値からのサイズは実行直前に検査する。非同期完了を所有する機構がないため lpOverlapped の非 NULL 値を明示的に拒否。小さすぎる出力領域、参照値の u32/BOOL/ポインタ幅への切り捨ても拒否し、回帰テストを追加した。

## 検証記録

- Linux の全ワークスペーステスト（通常スイートと loom を分けて実行）は通過。新規回帰テストも含む。
- `cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、WinMD 生成コードの `--check` を実行。
- Windows x64/i686 は全ターゲットをクロスコンパイルで検査。i686 の loom は依存 generator が非対応のため除外し、loom は Linux で検証する。
- Windows 実行と Application Verifier は GitHub Actions で確認する。この Linux 環境のコンパイル成功を Windows 実行成功とは扱わない。
- 既存 CI #25 の x64 Verifier 失敗は未解決の実行検証事項。次回失敗時に終了コード、Trace、Verifier XML を取得できるようにした。

## 保証の範囲

このレビューは全入力・全並行実行の安全性証明ではない。既存の任意プロセスへの Attach、スレッド停止中に他スレッドが保持するロック、COM の共有オブジェクト、未対応 ABI の観測範囲には引き続き設計上の制約がある。新機能の実装件数を検証済み件数とは数えない。
