## 更新 main の CI で追加確認した問題

- R15: CI run `43257264290` の Windows x64/x86 が `deleting_fiber_does_not_end_thread_capture` で失敗。Rust 1.99.1 の Windows TLS destructor 実装は fiber 上で cleanup を省略するため、削除時の誤通知だけでなく実際の thread exit も通知されない。Windows は `.CRT$XLB` の native TLS callback で `DLL_THREAD_DETACH` のみを処理するよう修正。既存の Windows 回帰テストは `2ee423b` の x86 CI で通過。native callback は Loader Lock 下で事前確保済み通知を atomic queue へ積むだけとし、ランタイムのロック取得・解放処理は次の管理パスまたは shutdown で行う。複数スレッドの通知と二重回収もテストする。
- R16: 同 run の fuzz-short は corpus 生成スクリプトの Permission denied で未実行。実行権限を修正し、85 seed の生成を確認した。

- R17: Runner の ReadFile/WriteFile は要求サイズと実バッファ容量を照合せず、ローカル確保した領域を非同期 I/O に渡して呼び出し直後に解放できた。既知のサイズは計画時、保存値からのサイズは実行直前に検査する。非同期完了を所有する機構がないため lpOverlapped の非 NULL 値を明示的に拒否。小さすぎる出力領域、参照値の u32/BOOL/ポインタ幅への切り捨ても拒否し、回帰テストを追加した。

- R18: ExitThread は Rust フレームを unwind しないため、通常 Detour の Drop に任せると実行中カウンタ・Arc・引数バッファを回収できない。Enter の記録後、元関数を呼ぶ前に記録用の所有権を解放し、TLS/DllMain 終了処理からの記録再開を止める。正常 Leave は捏造せず、実際の thread-detach 通知は従来の queue へ委ねる。ネイティブ CreateThread → ExitThread の終了コード、実行中カウンタ、Arc 数を確認する Windows 回帰テストを追加。終了処理中の API は記録しない制約があり、Verifier のアクセス違反が直った証拠とはまだ扱わない。

- R19: 再入ガードを立てる前に、destructor を持つ CALL_STACK / Agent の TLS を参照していた。初回参照の destructor 登録がメモリ確保を行うと、HeapAlloc 等の Detour がガードなしで再入できる。副作用のない Cell の確認後すぐにガードを立て、TLS 初期化まで保護するよう順序を修正。初期化中の再入拒否、利用不可と panic 時のガード解除を回帰テストで確認した。

- R20: Metadata の単一フィールド構造体をすべて内側の型へ変換していた。例えば float 1 個の実構造体は Windows x64 で整数レジスタを使い、float への置換は XMM レジスタを選んで ABI を壊す。NativeTypedef 属性がある別名型に変換を限定し、FXECHO_INITDATA の拒否と HANDLE 別名の維持を実 WinMD でテストした。現在選択済みの 136 生成 API はこの変更で減らない。未選択の 322 メソッドは ABI の確認が済むまで生成可能と数えない。

- R21: Inline Hook の設置時は停止スレッドの命令ポインタを検査する一方、解除時は元バイト列を書き戻す領域を検査していなかった。解除時にも全停止スレッドを確認し、範囲内または取得失敗なら未復元として返す。対象領域のネイティブループで待つスレッドを作り、解除を拒否してから正常に再開できる Windows 回帰テストを追加。

- R22: Windows x64 の非 Verifier 起動で Agent 初期化スレッドが `0xC0000005` を返す。CI run `43269547350` の診断で Agent DLL RVA `0xb48e`、Rust の REENTRANCY_DEPTH 取得処理、GS:[0x58] が NULL と確認した。`try_with` はこの native TLS vector の不存在を保護しない。Rust TLS の前に vector と DLL の TLS block を確認し、Loader の TLS 未準備／破棄後は記録を迂回するよう修正。元 API が TLS を破棄した場合も後処理で TLS に触らず、終了不明を正常完了に置き換えない。vector を一時的に NULL にしてガード入口を実行し、復元後に通常の記録へ戻れる Windows 回帰テストを追加。

- R23: `RoGetActivationFactory` を 2 引数で呼び、実際の第 2 引数 REFIID を出力ポインタと誤認していた。CI run `43271855579` の combase 内 AV は Agent の読み取り専用 IID 領域への書き込みだった。3 引数を recording / passthrough の両方で正しく転送し、要求 IID に従って追跡する。RoActivateInstance の返却値も既定インターフェイスと推測せず IInspectable と扱う。引数・出力・LastError の Windows 回帰テストを追加。
- R24: GUI の検証が全 callback の parent=0 を要求していた。同期メッセージ配送内の callback は呼び出し元 API を親とするため、同じスレッド上の先行 CallEnter を指すことを検証するよう修正。

- R25: SetWindowLongPtr の戻り値を nIndex に関係なく WndProc として逆変換していた。GWLP_USERDATA や追加領域の値がラッパーアドレスと一致するとアプリへ異なる値を返す。GWLP_WNDPROC のみに限定し、ユーザーデータ／追加領域／WndProc と LastError の Windows 回帰テストを追加。

- R26: 通常の Inline Hook 設置が内部 Nt API も対象にしていたため、通常モードでも内部フックを設置し、詳細モード側の設置数は already-hooked により 0 になった。通常 Inline / IAT 設置から内部 API を除き、詳細モードの専用経路だけで設置・集計する。直接 Nt API を import するアプリの IAT 計画も回帰テストで確認する。実際の NtCreateFile / NtClose と親 API の対応は既存 E2E で検証する。
- R27: Windows E2E の modules 検証が親の PID で子の出力ファイル名を照合し、Inline fixture は起動時未ロードの advapi32 を GetModuleHandle だけで解決していた。対象 PID を使用し、advapi32 の起動時 import を確保。SEH / replay の MSVC 起動は二重の cmd 引用符で失敗していたため、明示的な build.cmd 経由へ変更。失敗 Trace の無条件削除も停止した。

- R28: 性能ベンチは全 OS で API 本体を spin でモデル化するのに、Windows 実機の倍率測定と読める説明と固定の Windows 11 / x64 メタデータを使っていた。実行 OS / architecture を表示し、DLL 注入・Detour・実 GUI/API の性能目標をこのモデルで達成判定できないと明記した。

- R29: 注入専用 worker の ExitThread をアプリの呼び出しとして記録し、正常な file I/O Trace にも終了不明の損失を付けていた。初期化完了時にその専用スレッドを記録対象外へ移し、アプリの ExitThread は従来どおり正直に観測する。再実行の完全性条件は緩めない。Windows E2E で検証する。

- R30: native SEH fixture の HeapAlloc(HEAP_GENERATE_EXCEPTIONS, SIZE_MAX) が例外を呼び出し元へ伝えても Rust の CallGuard::Drop が実行されず、CallEnter と所有権が残った。生成 API の呼び出しを MSVC の `__try/__finally` で囲み、実際の unwind 時だけ記録状態を Option::take で一度だけ解放する。例外の捕捉・再送はしない。通常復帰、Rust panic、native SEH と実行中カウンタ／Arc／親スタックの回帰テストを追加。同じ境界を手書きファイル I/O、COM/WinRT、WndProc と検出 Hook にも適用する。非同期 I/O の仮登録は所有権を持つガードへ変更し、native SEH 時の取消も検証する。
- R31: kernel32 の FF25 import thunk だけをパッチし、API Set / CRT が直接呼ぶ kernelbase 実装を観測できなかった。読み取れる無条件 import thunk を最大 8 段たどり、共通実装をパッチする。Agent の Detour とモジュール外 relay には進まないため、再設置で自分自身をフックしない。実 DLL の解決先一致を Windows で検証する。

## Shutdown の再試行と所有権

解除が一部失敗しても Agent が `STATE.take()` で復元情報を捨てていたため、次の
Shutdown は NotInitialized となり、無効化済み Runtime と残存 Hook を回収できなかった。
初期化と終了を直列化し、未復元の記述子だけを STATE に残す。成功済みの箇所は
再試行で書き戻さず、公開済みトランポリンの寿命も変えない。進行中呼び出しの
完了待ちがタイムアウトした場合も、復元だけで完了扱いにせず次の Shutdown へ持ち越す。

Host は Agent が明示的に Incomplete を返した完了済み呼び出しだけ 1 回再試行する。
remote call 自体の失敗・タイムアウトは worker が動いている可能性があるため再試行しない。
2 回目も失敗なら従来の未完了報告を保つ。対象モジュールが元のアドレスにロードされ、
設置箇所を他の Hook 管理者が並行して変更しないという既存の復元契約は残る。

Windows 回帰テストは未コミットページで IAT 復元失敗を起こし、失敗状態の保持、
再初期化拒否、失敗箇所だけの再試行、復元済みスロットへのアプリの変更の維持、
進行中呼び出しの完了待ち再試行を検査する。Inline は IP 範囲内で拒否した後、
スレッド終了後に再試行して元命令を復元する。実機実行は CI で確認する。

ReadFile の出力取得は、観測した転送バイト数を元の要求サイズと照合していなかった。
同期 leave、OVERLAPPED の即時完了、後から観測した完了の全経路へ入口の要求長を渡す。
転送長が要求長を超えた場合は、生の転送長を保持したまま data を Unsupported とし、
バッファに一度もアクセスしない。x64 OVERLAPPED.InternalHigh の u32 切り捨ても拒否する。
これらの不整合は切り詰めた正常データとして扱わず、Coverage 台帳の取得状態と既存の
replay 拒否へ反映する。0 / 1 / 4096 / u32 上限近辺の境界、
要求長ちょうどの正常値、同期・非同期でのメモリ未参照と生値保持を回帰テストで検査する。

Host は有効な Compact 値列の取得状態も集計し、Unreadable / Unsupported /
Truncated / LimitExceeded があれば最終 Semantic Completeness を Degraded にする。
符号化検証と同じ走査で検出し、追加の値列デコード・メモリ確保はしない。
成功時の残留 last-error を表す Stale は情報不足とは区別する。
実 Agent → Ring → Host → Trace Finalization の回帰テストで全 6 状態を検査し、
フィールド不足が Event Integrity を誤って落とさないことも確認した。
これは保存された値列の評価であり、未観測 API や Profile で保存しない値の完全性を
証明するものではない。

## Runtime 取得の世代付き TLS キャッシュ
